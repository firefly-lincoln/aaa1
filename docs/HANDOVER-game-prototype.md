## 一、这是什么

单文件 HTML 游戏原型 —— 玩家扮演城市应急管理中心指挥官，
通过接听报警电话、判断事件性质、派发警/医/消单位来处置事件。

**参考基调**：`Radio Commander`（信息不完整带来的压力）+ `112 Operator`（调度手感）。
**核心机制**：**单位位置是「上报位置」而不是真实位置** —— 玩家看到的位置带误差，
这制造了"信息不对称"这个核心张力。

**设计文档**（工作区根目录）：
`游戏设计-应急指挥.md`、`游戏设计-指挥官与上报位置.md`、`游戏设计-参考游戏机制核实.md`

**世界观（方案 A，已实现）**：虚构美国锈带小城 **Grayharbor**（俄亥俄州，人口 18 万），
时间 **1994 年 10 月**。老钢铁厂倒闭三年，应急中心是联邦拨款刚装的"复兴示范点"。
爆发源是 **The Mill Complex**（废弃纺织厂区）。

## 三、我犯过的错（带证据，请勿重复）

> 这一节是本文档的核心。我在这 93 轮里**反复犯同类错误**，
> 每个都附了当时的原始观测，你可以对照识别自己是否正在重演。

### 错误 1：反复"改参数 → 截图目测 → 再改"，而不先插桩

**建筑立体感这件事，用户提了 4 次，我改了 4 轮才修对。**

| 轮次 | 我的做法 | 结果 |
|---|---|---|
| 1 | 调 `OBLIQUE` 斜切常量 | 屋顶与底面重合 → "一张立着的纸" |
| 2 | 加底部色带 | 仍无透视面 |
| 3 | 改 `dx = wallH*0.34` | 西墙变成 2px 细条 |
| 4 | **先看放大图找规律** | 发现"**只有最南一排有墙**" → 定位到墙被邻居屋顶盖掉 |

**真正的根因是结构性的**：墙画在**脚印之外**，被相邻建筑整块覆盖。
调任何参数都不会好。

**教训**：
- **"哪些有、哪些没有"这类分布规律，比"好不好看"更能定位结构性 bug。**
- 用户描述形状的能力很强（"贴图"、"立着的纸被照出阴影"），**把他的描述当成观测数据**。

### 错误 2：河流问题花了 5 轮，因为一直在看截图猜

黑块 → 猜桥墩 → 猜颜色判定 → 猜裁剪 → **全错**。

**转折点是停止看图、改成打印几何数据**：
```
widMin: 5   widMed: 5   widMax: 7      ← 宽度稳定
rowsWithWater: 92                       ← 92 行全有水
suspicious: []                          ← 无异常行
```
数据完全正常 → 说明问题在**绘制**不在**数据**。于是改用"把多边形填成洋红单独渲染"来定位。

**最终修法**：放弃贝塞尔/椭圆/多边形三种方案，
改用**逐行四边形拼接**（第 y 行与 y+1 行共用一对采样点）——
**构造上不可能留缝、不可能自交**，而不是靠调参。

**教训**：
- **依赖"构造上的保证"，而不是"调参调出来的正确"。**
- 数据探针 > 视觉目测。**先证明数据对不对，再怀疑绘制。**

### 错误 3：探针本身算错，反被误导两轮

我写像素探针时用了：
```js
const sc = src.width / M.width;   // 1920 / 120 = 16   ✗ 错
```
`M.width` 是**格数**，而实际比例是 `cv.width / MW`（地图**像素**宽）= **2**。

**坐标偏了 8 倍**，我读的"黑色像素"根本不是河，是旁边的建筑影。
白绕了两轮。

**教训**：**探针必须先自证正确** —— 先读一个已知位置验证。
**错误的数据比没有数据更糟。**

### 错误 4：把 PowerShell 的显示问题误判成文件损坏

我看到文件内容显示为 `'绌哄湴'`（应为 `'空地'`），**当即断言"文件损坏了"**，还复制了备份。

**实际验证结果**：
```
替换字符(FFFD): 0
典型 GBK 乱码字符: 0
```
**文件完全干净** —— 那是 PowerShell 控制台按 GBK 渲染 UTF-8 的**显示问题**。

**教训**：
- **下"文件损坏"这种结论前，必须做字节级验证。**
- 这正是环境文档里已有的铁律（第 6 条：PowerShell 读 UTF-8 要指定编码）—— **我知道这条，还是犯了。**

### 错误 5：数组当对象用（一个属性名写错，整个功能失效）

区块档案面板"驻在设施"**每个区都显示"无驻在设施"**：
```js
const sts = STATIONS.filter(s => s.zone === d.id);   // ✗ STATIONS 是数组！
```
`STATIONS` 每项是 `[id, 名称, 类型, 分区, 规模]` —— **没有 `.zone` 属性**。
应为 `s[3] === d.id`。

**教训**：**"全都失败"通常指向取值错误，"部分失败"才指向逻辑错误。**

### 错误 6：对已生成的脚本文件做字符串拼接修改 → 改坏 / 静默不生效

我写插桩脚本去改 `_genmap.mjs`，`replace()` 锚点没匹配上，
**结果是原样复制**（看起来"生成了新文件"，实际没改），
于是我的插桩日志根本没打印，我据此得出"滨河带没执行"的错误结论。

**教训**：
- **改源码用 `edit` 工具（精确匹配 + 报错），不要用字符串拼接脚本。**
- 插桩失败时**先确认插桩本身生效**（比如故意打印一行常量），再解读输出。

### 错误 7：同一个逻辑写在多处，改一处漏一处（**这条我犯了至少 5 次**）

| 位置 | 后果 |
|---|---|
| 三个测试文件各写一份 `advance()` | 改玩法后两个测试用"影子实现"，测不出问题 |
| 倍速按钮与键盘各写一份 `setSp` | 鼠标点暂停后 `lastSpeed` 记录不到 |
| 8 处内联 `onclick` + 1 处 `d.onclick` 直接赋值 | 面板重建时丢失，**分两次才修完** |
| `riverCenter` 的坐标口径混用两套比例 | 滨河带整体错位，东岸反复"光秃" |

**教训**：
- **发现同一逻辑出现两次时，立刻合并 —— 这是未来 bug 的种子。**
- 修复一类问题时，**先全量搜索同类写法**（我用 `Select-String` 数了一下才发现
  展开按钮是第 9 处，上一轮漏掉了）。

### 错误 8：把"测试失败"当成"代码错了"

多次出现：测试报红 → 我改代码 → 其实**是测试的模型不对**。

具体案例：
- 测试 `advance()` 把 `S.t += 2` 当成一个 tick（真实是 `0.16 × speed`）
- 测试用**过期坐标**点击（卡片重排后点到了被裁剪的别处）
- 测试用**绝对位移**断言（长车程必然不满足）

**教训**：**测试失败时，先问"测试测的是不是真实路径"，再问"代码错没错"。**

### 错误 9：在 CDP 截图里用页面覆盖层裁剪 canvas

我加了 `position:fixed;left:0;top:0` 的调试层去裁河道，
结果被 CSS 缩放（19%）和 `image-rendering` 干扰，**坐标一直不对**。

**可靠做法**（已验证）：
```js
// ① 先把 canvas 导出成 PNG
document.getElementById('map').toDataURL('image/png')
// ② 写一个【只含 <img>】的干净 HTML，用 transform 放大定位
// ③ 打开它再截图
```
这样坐标完全可控。脚本模式见 `_shot\` 下曾用过的 `closeup` 思路。

## 四、代码里的主要陷阱

### 1. `renderQueue()` 每 125ms 用 `innerHTML` 重建整个面板

**任何直接赋值的事件处理器都会丢**：
```js
d.onclick = ...            // ✗ 重建后失效
```

**必须用事件委托**：
```js
// 绑在稳定的父容器上，监听 pointerdown（比重建更早触发）
wireCallActions(document.getElementById('queue'), 'data-act');
```
现有动作标记：`expand|id` · `class|id|值` · `pick|id` · `send|id|unitId` · `uncls|id` · `conc|id|值`

**新增按钮时一定要走这套，不要写 `onclick`。**

### 2. 累积距离模型（移动系统）

```js
u.segs   // 段表 [{x0,y0,x1,y1,len}]
u.total  // 总长
u.s      // 已行驶距离（唯一状态）
posAt(u, s)          // 按距离查表求位置
stepAlongPath(u, dt) // dt 由主循环传，【绝不能在这里再乘 speed】
```

**历史上踩过的坑**：
- `S.t` 已乘倍速，位置里又乘一次 → **4× 实际跑 16 倍**
- 逐段状态机（`fromX/moveT/beginLeg`）在换段处**跳变 11 格** → 已废弃
- 浮点索引 `sm[44.5]` → `undefined` → `NaN` → `ellipse()` 抛异常中断绘制

### 3. 时间与倍速

```js
const dt = (S.tickMs/1000) * S.speed;    // 一个 tick 推进的游戏秒数
```
- **1× 严格等于真实时间**（曾误乘 6，导致所有计时快 6 倍）
- 主循环用 `requestAnimationFrame`，**渲染 60fps，逻辑固定步长**
- `renderAlpha` 用于渲染插值（否则 4× 下"每帧跳一格"）

### 4. 地图坐标口径

地图数据 `MAP.width/height` 是**格数**，`tile=8`。
- **格数 → 地图坐标**：`× tile`
- **地图坐标 → canvas 像素**：`× (cv.width / (MAP.width*tile))`

**生成器里的三套比例不要混用**：
```js
const sc  = v => Math.round(v * W / 120);   // x 方向（v6 基准宽 120）
const scy = v => Math.round(v * H / 92);    // y 方向（v6 基准高 92）
const RX  = W / 120;                        // 河流专用，与 sc 同口径
```
**混用会导致"某个区域整体错位"这类难查的问题**（滨河带因此反复失败 3 次）。

### 5. 坐标系里有 `withUpright`

地图用斜投影，但**单位图标和文字要正立** —— 必须包在 `withUpright(x, y, fn)` 里。

## 五、测试约定

### 每个测试文件必须注入的沙箱

```js
sb = {
  document: { /* 需要 addEventListener / removeEventListener /
                 exitFullscreen / requestFullscreen / fullscreenElement */ },
  requestAnimationFrame: () => 0,       // 主循环用它，缺了会 ReferenceError
  performance: { now: () => 0 },
  setTimeout, clearTimeout, setInterval, clearInterval,
  Uint8Array, Int32Array,
  // ...
}
```

**canvas 桩必须包含**：
`fillRect, clearRect, strokeRect, drawImage, fillText, strokeText, measureText,
beginPath, arc, ellipse, fill, stroke, setLineDash, moveTo, lineTo, closePath,
save, restore, scale, translate, transform, setTransform, bezierCurveTo,
quadraticCurveTo, clip, createLinearGradient, createRadialGradient,
globalAlpha, lineJoin, lineCap, globalCompositeOperation`

### ⚠️ 推进时间的唯一正确写法

```js
function advance(sec){
  const t0 = S.t + sec;
  while (S.t < t0){
    S.t += (S.tickMs/1000) * S.speed;
    tickTravel(); tickPatrol(); tickReturns(); tickPhases(); tickAid();
  }
}
```

**历史上写错过两次**：
- `S.t += 2; tickPhases()` —— 把 20 游戏秒当一个 tick，**且完全不驱动单位移动**
- 内联复制插值代码 —— 玩法改了以后成了"影子实现"，位置永远不动但测试不报错

### 测试暴露的机制要手动加进 `globalThis.__xxx`

测试通过 `new vm.Script(js + ';globalThis.__S=S;...')` 暴露内部符号。
**新增需要测试的函数时，记得加进去。**

### 关键：受限模式下 headless Edge 起不来

如果会话的文件策略是 **`workspace-write`** 而不是 `danger-full-access`：

```
FATAL:mojo\public\cpp\platform\platform_channel.cc:183] Check failed: 拒绝访问。(0x5)
```

**Edge headless 需要命名管道做 IPC，受限模式禁止** →
**你将失去全部截图验证能力**。

**这不是你的脚本坏了。** 让用户把文件策略改成 `danger-full-access`。

### 不要随便杀 msedge

我为了重试 CDP **直接 `Stop-Process msedge`**，杀掉了用户正在用的浏览器窗口。
**只清理自己启动的实例**（按 `--user-data-dir` 或命令行特征过滤）：

```powershell
Get-CimInstance Win32_Process -Filter "Name='msedge.exe'" |
  Where-Object { $_.CommandLine -like '*headless*' -or $_.CommandLine -like '*udXX*' } |
  ForEach-Object { Stop-Process -Id $_.ProcessId -Force }
```

## 八、给后续 AI 的行动准则

1. **先只读侦察，再动手**
2. **推理不通时先插桩打印数据** —— 我在"猜根因"上浪费的时间远超插桩成本
3. **探针先自证正确**（先读一个已知位置），否则错误数据会误导你
4. **测试报红时，先确认测试走的是不是真实路径**
5. **发现同一逻辑存在两处，立刻合并**
6. **改一类问题时全量搜索同类写法**（`Select-String` 数一下有几处）
7. **改源码用 `edit` 工具，不要用字符串拼接脚本**
8. **视觉结论必须来自截图**，不能靠推理（而截图能力可能因沙箱受限）
9. **下"文件损坏/数据丢失"这类结论前，做验证**
10. **用户会实际游玩每一个版本** —— 他的反馈是最高优先级的信息源，
    而且他描述形状/手感的能力很强，**把他的话当观测数据用**
